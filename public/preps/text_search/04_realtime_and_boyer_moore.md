# KMP реального времени и Бойер и Мур

## Табличный KMP

В обычном KMP суммарный проход линейный, но на одном байте возможна цепочка откатов. Термин «реальное время» здесь означает ограниченное постоянной время обработки каждого следующего байта после подготовки. Построим все переходы заранее. [Полная программа](code/05_kmp_realtime.cpp), [соответствующий лекционный пример](../lecture_31_10/kmp_realtime.cpp).

Состояние `q` есть длина префикса образца, совпавшего с суффиксом прочитанного текста. Возможны состояния `0..m`, включая полное совпадение. Таблица `go[q][c]` хранит следующее состояние после байта `c`.

Правила построения:

1. В строке состояния 0 все переходы ведут в 0, кроме `P[0]`, который ведёт в 1.
2. Для `q > 0` копируем строку `go[pi[q - 1]]`. Это все переходы после отката к следующей границе.
3. Если `q < m`, переопределяем переход по `P[q]`: он ведёт в `q + 1`.
4. Строка состояния `m` тоже нужна. Она полностью наследует переходы по границе и сохраняет перекрытия после успеха.

Корректность: при совпадении следующий префикс увеличивается на один. При несовпадении обычный KMP начал бы с `pi[q - 1]`. Таблица этого меньшего состояния уже готова, потому что `pi[q - 1] < q`. Мы заранее записываем результат именно этой цепочки сравнений.

Таблица для `aba` по двум встречающимся буквам:

| `q` | `a` | `b` |
| --- | --- | --- |
| 0 | 1 | 0 |
| 1 | 1 | 2 |
| 2 | 3 | 0 |
| 3 | 1 | 2 |

Остальные байты ведут в 0. Например, из состояния 3 по `b` идём в 2, поскольку суффикс `ab` строки `abab` снова совпадает с префиксом образца. В `feed` остаётся одно обращение к таблице и проверка `state == m`.

Есть `m + 1` строк по `σ` значений. Подготовка и память `O(mσ)`, проход `O(n + z)`. В коде `σ = 256`. Размер данных таблицы вычисляется как `(m + 1) * 256 * sizeof(int)` байтов, без служебных полей контейнера. При четырёхбайтовом `int` и `m = 100000` это `100001 * 256 * 4 = 102401024` байта, примерно 97.66 MiB после деления на `2^20`. Сначала сравни это с лимитом памяти.

## Бойер и Мур: сравниваем справа налево

На каждом выравнивании образец сравнивается с текстом от последнего символа к первому. Несовпадение и уже совпавший суффикс дают ограничения на следующие допустимые начала. Вместо сдвига на один выбираем безопасный скачок. Идея двух правил изложена в [исходной статье Бойера и Мура](https://www.cs.utexas.edu/~moore/publications/fstrpos.pdf). Здесь разбирается конкретная [реализация с обоими правилами](code/06_boyer_moore.cpp).

### Правило плохого символа

Заранее вычисляем `last[c]`, последнее положение байта `c` в образце, или `-1`, если его нет. Пусть несовпадение произошло в позиции `j` образца с байтом текста `c`. Безопасный сдвиг:

```text
bad = max(1, j - last[c])
```

Если `c` отсутствует, сдвиг равен `j + 1`: этот байт текста должен оказаться левее нового начала образца. Если его последнее положение левее `j`, совмещаем его с текущим байтом. Если последнее положение правее `j`, правило даёт только 1, поскольку отрицательный сдвиг не продвигает поиск.

Для `P = abcd` и окна `abxd` справа уже совпал `d`, затем `c != x` при `j = 2`. Буквы `x` в образце нет, значит, `bad = 2 - (-1) = 3`. Начала со сдвигом 1 и 2 тоже накрывают `x` каким-то символом образца и невозможны.

### Правило хорошего суффикса

Пусть после несовпадения в `j` уже совпал суффикс `P[j+1:m)`. Возможны два способа сохранить его при сдвиге:

1. Совместить его с другим вхождением в образце, у которого предшествующий символ отличается от `P[j]`. Равный предшествующий символ повторил бы уже известное несовпадение.
2. Если такого вхождения нет, совместить самый длинный суффикс совпавшей части с префиксом образца. Если даже непустого совпадения нет, сдвинуть на всю длину.

В коде `shift[j + 1]` задаёт сдвиг после несовпадения в `j`, а `shift[0]` после полного совпадения. При несовпадении берётся `max(bad, shift[j + 1])`. Каждое правило исключает все меньшие сдвиги по своему условию, поэтому максимум также безопасен. При полном совпадении сохраняем перекрытие с самой длинной границей.

Пример `P = ababa`. После полного совпадения можно совместить суффикс `aba` с префиксом `aba`, сдвиг равен `5 - 3 = 2`. Так будут найдены начала 0 и 2 в тексте `abababa`. Пример сильного правила: в окне `abbba` совпал суффикс `ba`, а в `j = 2` буква образца `a` не совпала с `b`. Другое `ba` в образце имеет ту же предшествующую `a`, поэтому его использовать бессмысленно. Остаётся совместить последнюю `a` с префиксом `a`, сдвиг 4.

### Как читать `goodSuffixSimple`

Массив `border[i]` хранит начало следующего более короткого суффикса, который является собственной границей суффикса `P[i:m)`. Для пустого суффикса служебное значение `border[m] = m + 1`. Это другой массив, он не равен `pi`.

В первом проходе `i` движется от `m` к 0, а `j` указывает на текущую границу. При `P[i - 1] != P[j - 1]` найдено подходящее более раннее вхождение суффикса с отличающимся предшественником. Если `shift[j]` ещё не заполнено, записывается расстояние `j - i`. Затем `j = border[j]` проверяет более короткую границу. После выхода из внутреннего цикла уменьшаются `i` и `j`, и записывается `border[i]`.

Второй проход заполняет оставшиеся нули сдвигами по границам всего образца. Именно он покрывает случай совмещения только части суффикса с префиксом и полный успех. Для `ababa` получается:

```text
индекс       0 1 2 3 4 5
shift        2 2 2 4 4 1
```

Например, несовпадение в `j = 2` использует `shift[3] = 4`, а успех использует `shift[0] = 2`. Эти значения можно сверить вызовом `goodSuffixSimple("ababa")`.

Первый проход вычисляет цепочки границ линейно: внешние шаги перемещают `i` и `j` влево на единицу, а внутренние переходы перемещают `j` вправо по строго более коротким границам. Всего таких перемещений `O(m)`, поскольку `j` ограничен диапазоном до `m + 1`. Второй проход также линейный. Вместе с таблицей последних позиций подготовка занимает `O(m + σ)`, память столько же.

### Честная оценка поиска

В этой программе нет правила Галиля и запоминания уже проверенных перекрытий. Для образца из `m` букв `a` в тексте из `n` букв `a` каждое выравнивание успешно, проверяются `m` символов, затем сдвиг равен 1. Получается `(n - m + 1) * m` сравнений при `m <= n`. Поэтому для поиска всех вхождений здесь используем верхнюю границу `O(nm)`. Нельзя переносить оценки других вариантов на этот код по одному названию алгоритма.

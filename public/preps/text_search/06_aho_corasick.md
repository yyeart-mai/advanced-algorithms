# Ахо и Корасик

## Когда нужен

Есть `k` образцов, суммарно `L` байтов, и текст длины `n`. Запуск отдельного KMP для каждого образца требует `O(L + kn)` времени без учёта вывода. Идея Ахо и Корасика: объединить префиксы в trie и обработать текст одним проходом. Автомат, суффиксные переходы и выдача совпадений описаны в [статье Ахо и Корасик](https://cr.yp.to/bib/1975/aho.pdf) и [лекции CMU](https://www.cs.cmu.edu/~ckingsf/bioinfo-lectures/multipattern.pdf).

## Какие поля есть у вершины

В [классическом коде](code/09_aho_corasick.cpp):

- `go[c]` сначала хранит ребёнка trie по байту `c` или `-1`. После построения это полный переход автомата.
- `link` ведёт в вершину наибольшего собственного суффикса текущего пути, который тоже является префиксом какого-то образца.
- `ids` хранит номера образцов, которые заканчиваются именно здесь.
- `exit` ведёт в ближайшую терминальную вершину по суффиксным ссылкам, либо равен `-1`.

Корень имеет номер 0 и суффиксную ссылку в себя. Пустые образцы игнорируются, поэтому он не терминальный. Одинаковые образцы получают разные номера в одном списке `ids` и сохраняются в ответе.

Если путь вершины обозначает `she`, а в словаре есть `he`, её суффиксная ссылка может вести в `he`. Если есть ещё `e`, из `he` ссылка ведёт в `e`. После чтения `she` надо выдать все три образца, а не только `she`. Назначение failure-ссылки и отдельной выдачи ответов разобрано также в [материалах CMU о множественном поиске](https://www.cs.cmu.edu/~ab/CMU/Week%2010-%20Strings%20Search/print04.pdf).

## Построение в ширину

Сначала вставляем все образцы в обычный trie и сохраняем их длины. Затем запускаем BFS, чтобы короткие префиксы обрабатывались раньше длинных.

1. Для корня отсутствующие переходы заменяем на 0. Его настоящих детей кладём в очередь, их `link` уже равен 0.
2. Берём вершину `v`, обозначаем `u = link[v]`. Полная таблица `go[u]` уже известна, поскольку глубина `u` меньше.
3. Если `u` терминальна, ставим `exit[v] = u`. Иначе наследуем `exit[u]`.
4. Для отсутствующего перехода записываем `go[v][c] = go[u][c]`.
5. Для настоящего ребёнка `w` записываем `link[w] = go[u][c]` и кладём `w` в очередь.

Почему шаг 5 верен: более короткий подходящий суффикс строки пути `v` задаёт `u`. При добавлении байта `c` нужно найти самый длинный подходящий суффикс продолженной строки, а этот результат уже вычислен как переход `go[u][c]`.

После заполнения переходов trie уже нельзя свободно дополнять новыми образцами тем же методом `add`: отсутствующие рёбра заменены переходами автомата. Поэтому конструктор получает весь словарь сразу и только затем вызывает `build`.

## Поиск и выдача

Храним вершину `v`. Для каждого байта текста выполняем `v = go[v][c]`. Теперь путь вершины есть самый длинный суффикс прочитанного текста, который является префиксом образца. Выдаём `ids[v]`, затем идём по `exit` и выдаём списки найденных терминальных суффиксов.

Если образец с номером `id` имеет длину `lengths[id]` и заканчивается в `i`, начало равно `i - lengths[id] + 1`. Этот же подсчёт использовался в KMP.

Пример:

```text
2
aba
ba
ababa
```

Образцы имеют номера 0 и 1. После первых двух байтов автомат находится в `ab`, ответов пока нет. На третьем байте оказывается в `aba`, выдаёт `aba` и терминальный суффикс `ba`. На четвёртом байте переход из `aba` по `b` попадает в `ab`, на пятом снова в `aba`.

```text
0 0
1 1
2 0
3 1
```

Порядок в этой реализации: сначала по позиции окончания, затем текущая терминальная вершина и всё более короткие терминальные суффиксы. Внутри одной вершины номера идут в порядке вставки. Общей сортировки по началу или номеру образца нет. Для `he`, `she`, `e` в тексте `she` сначала выдаётся `she`, затем `he`, затем `e`.

## Время и память

Вершин не больше `L + 1`. Вставка просматривает `L` байтов, каждая новая вершина инициализирует `σ` переходов. BFS также перебирает `σ` переходов в каждой вершине. Хранение длин требует `O(k)` даже если образцы пусты. Получаем подготовку `O(L + vσ + k)` и память `O(vσ + k)`.

На каждый байт текста один табличный переход. Дополнительно проверяется текущая вершина и цепочка `exit`. Каждая вершина, достигнутая через `exit`, содержит хотя бы один номер образца и выдаёт хотя бы один ответ. Поэтому все такие переходы можно отнести к выдаваемым совпадениям. Итого `O(n + z)` времени. Вектор ответа добавляет `O(z)` памяти. При большом ответе можно печатать совпадения сразу вместо накопления.

В простом [лекционном классе](../lecture_07_11/aho_corasick.cpp) списки выходов суффиксных ссылок копируются в вершины. В этой папке вместо копирования стоит `exit`, чтобы размер списков был суммарно `O(k)`. Оба варианта классические, шаблонов функций здесь нет.

## Частые ошибки

- Выдавать только `ids[v]` и терять короткие образцы, заканчивающиеся в той же позиции.
- Проходить всю цепочку `link` на каждом байте даже через нетерминальные вершины. Это не даёт приведённого обоснования `O(n + z)` для выдачи.
- Дублировать образцы в словаре и случайно терять их номера через `bool terminal`.
- Забыть, что сам ответ может быть большим. Для образцов `a`, `aa`, ..., `a^r` в тексте `a^n` число совпадений есть сумма `n - d + 1` по `1 <= d <= min(r, n)`.

## Если требуется только число вхождений

Не обязательно перечислять все совпадения. Можно на каждом байте увеличивать счётчик посещений текущей вершины, затем пройти вершины в обратном порядке BFS и прибавить `count[v]` к `count[link[v]]`. После этого счётчик терминальной вершины равен числу вхождений каждого заканчивающегося там образца. Обоснование и задача находятся в [практике](09_practice.md). Для счётчиков выбирай тип по максимальному возможному ответу.

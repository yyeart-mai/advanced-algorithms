# Термины и наивный поиск

## Какую задачу решаем

Есть текст `T` длины `n` и образец `P` длины `m`. Нужно найти все начала `s`, для которых `T[s + j] == P[j]` при каждом `0 <= j < m`. Подстрока непрерывна. Подпоследовательность может пропускать символы: `ac` является подпоследовательностью `abc`, но не её подстрокой. Именно поиск непрерывного образца рассматривается в [определении задачи в материалах CMU](https://www.cs.cmu.edu/~ckingsf/bioinfo-lectures/zalg.pdf).

Используем полуинтервал `[l, r)`: левая граница включена, правая исключена, длина равна `r - l`. Например, в `banana` подстрока `[1, 4)` есть `ana`. Префикс начинается в нуле, суффикс заканчивается в конце строки. Собственный префикс короче всей рассматриваемой строки. Граница строки, или border, есть её собственный префикс, одновременно являющийся суффиксом. У `ababa` непустые границы `a` и `aba`, их длины равны 1 и 3 по прямому подсчёту букв.

Для `P = aba`, `T = ababa` ответ `0, 2`: второе вхождение использует последний символ первого. Это перекрытие. Сдвигать образец на его длину после каждого успеха нельзя, если условие требует все вхождения.

## Наивный алгоритм

Перебери начала `s` от `0` до `n - m` включительно. Для каждого начала сравнивай символы слева направо. Первое несовпадение означает, что это начало не подходит. Если проверены все `m` символов, добавь `s` в ответ. [Полная программа](code/01_naive.cpp).

Пример `P = aba`, `T = ababa`:

| Начало | Сравнения | Итог |
| --- | --- | --- |
| 0 | `a=a`, `b=b`, `a=a` | добавить 0 |
| 1 | `a!=b` | остановить эту проверку |
| 2 | `a=a`, `b=b`, `a=a` | добавить 2 |

Корректность следует из перебора всех допустимых начал и проверки определения вхождения для каждого. Начал `n - m + 1`, когда `m <= n`, на каждое не более `m` сравнений. Итого `O(nm)` в худшем случае. Если `m > n`, цикл не выполняется. Дополнительная память, помимо массива ответа, постоянна.

Плохой пример: `P = aaaab`, `T = aaaaaaaaaa`. На каждом допустимом начале совпадают четыре `a`, затем обнаруживается несовпадение с `b`. Для произвольных длин семейство `a...ab` против `a...a` заставляет повторять почти все сравнения. Следующие алгоритмы переиспользуют сведения о совпавших частях.

## Что проверить до выбора алгоритма

- Требуются все позиции, первая позиция, число вхождений или только существование?
- Допускаются перекрытия? Поиск точный, регистрозависимый? Как задан алфавит?
- Один образец или множество? Один текст или повторные запросы к одному тексту?
- Какие ограничения на длины, память и размер ответа?
- Что условие говорит о пустой строке и нумерации позиций?

В этих программах пустой образец игнорируется. Это выбранное соглашение интерфейса. Если задача считает его вхождения во всех границах строки, ответ содержит `n + 1` позиций, поскольку есть границы до первого байта, между соседними байтами и после последнего.

## Ошибки в C++

`string::size()` возвращает беззнаковый тип. Выражение `text.size() - pattern.size()` при более длинном образце не даёт отрицательное число. В учебном переборе длины заранее переведены в `int`. В вариантах на `size_t` сначала нужна проверка `m <= n`.

`cin >> text` обрывает ввод на пробеле. Для поиска в строке с пробелами используй `getline`. После чтения числа перед `getline` нужно пропустить оставшийся перевод строки, как в [Ахо и Корасике](code/09_aho_corasick.cpp).

Для индексации таблицы по байту используй `static_cast<unsigned char>(c)`, как в [KMP с таблицей](code/05_kmp_realtime.cpp). Обычный `char` может быть знаковым. Копирование через `substr` внутри каждого сравнения также меняет реальную стоимость алгоритма, поэтому поисковые примеры сравнивают символы по индексам.

## Проверка понимания

Объясни, почему у `aa` в `aaaa` три вхождения. Выпиши начала и сравни каждый отрезок длины два. Затем придумай пример без единого вхождения, на котором наивный поиск всё равно выполняет много сравнений.

# Хеш-таблицы в контексте строк

В [лекции 24.10](../lecture_24_10/README.md) вместе с поиском подстроки перечислены хеш-таблицы. Это полезная отдельная основа для хранения слов и счётчиков. В этой главе рассматриваются таблицы из лекционных примеров, без добавления хеширования подстрок в обязательный набор алгоритмов поиска.

## Хеш не доказывает равенство

Хеш-функция переводит ключ, например слово, в число. Номер корзины получается из этого числа и размера таблицы. Разным строкам может соответствовать один номер, это коллизия. Поэтому после совпадения хеша или корзины проверяют сами ключи.

Для наглядного примера возьмём сумму кодов байтов по модулю размера таблицы. Строки `ab` и `ba` имеют одинаковую сумму, потому что слагаемые те же. Они попадут в одну корзину, но останутся разными ключами. Это демонстрация коллизии, а не рекомендуемая хеш-функция.

В [простом множестве строк с цепочками](../lecture_24_10/01_hash_table.cpp) вычисление хеша просматривает все символы, затем поиск сравнивает строки в нужной корзине. Равенство строк не заменяется равенством чисел.

## Цепочки

У каждой корзины есть список ключей. Для поиска вычисляем корзину и перебираем её элементы. Для вставки сначала проверяем отсутствие ключа, затем добавляем его. Для удаления находим ключ и убираем его из списка.

Пусть `N` есть число ключей, `B` есть число корзин, `α = N / B` есть коэффициент заполнения. При равномерном распределении ожидаемая длина цепочки порядка `α`. Для строк длины до `d` вычисление хеша требует `O(d)`, а одно полное сравнение строк в худшем случае тоже `O(d)`. Поэтому при таком предположении безопасная ожидаемая оценка поиска `O(d(1 + α))`. Если все ключи попали в одну корзину, она превращается в `O(Nd)`.

Это вывод по числу элементов корзины и посимвольному сравнению, а не обещание постоянного времени для любой строки. При увеличении таблицы номера корзин пересчитывают для всех ключей.

## Открытая адресация

Все ключи лежат в самой таблице. Если исходная ячейка занята, линейное пробирование проверяет следующие ячейки с переходом по модулю размера таблицы. [Классический вариант для целых](../lecture_24_10/open_addressing.cpp) использует три состояния:

- `Empty`: ячейка никогда не занималась после последней перестройки.
- `Occupied`: здесь действующий ключ.
- `Deleted`: ключ удалён, но цепочку пробирования обрывать нельзя.

Предположим, ключи `x` и `y` имеют одну исходную ячейку. `x` занял её, `y` оказался в следующей. Если удалить `x` и сделать его ячейку `Empty`, поиск `y` остановится слишком рано. Маркер `Deleted` заставляет продолжить пробирование.

При вставке удалённую ячейку можно запомнить как место для нового ключа, но поиск дубликата надо продолжить до существующего ключа или настоящей пустой ячейки. Иначе в таблице появится второй экземпляр того же ключа. Цикл пробирования должен быть ограничен числом ячеек, чтобы заполненная таблица не дала бесконечный цикл.

При высокой заполненности и скоплениях занятых ячеек пробирование удлиняется. Одна операция может проверить всю таблицу. Перестройка в больший массив и повторная вставка действующих ключей освобождают маркеры удалений. Сам факт использования хеширования не гарантирует худшее время `O(1)`.

## Связь с поиском в тексте

Словарь строк отвечает на вопрос о целых ключах, как и trie. Перебирать все подстроки, создавать для каждой `substr` и проверять в таблице не означает получить линейный поиск. Число непустых подстрок с учётом разных пар границ равно `n(n + 1)/2`, это сумма `n + (n - 1) + ... + 1`. Добавляется копирование и хеширование символов.

Для одного образца в тексте в этой папке есть KMP и Z, для множества образцов Ахо и Корасик. Полиномиальные хеши подстрок и Рабин и Карп являются отдельными техниками. Их наличие нельзя вывести из одного упоминания хеш-таблиц в списке лекций.

## Проверка понимания

Объясни разницу между одинаковой корзиной и одинаковым ключом. Нарисуй таблицу с двумя ключами, попавшими в соседние ячейки из-за коллизии, удали первый и вручную выполни поиск второго. Почему `Deleted` нельзя заменить на `Empty`?

# Спецификация лабораторной работы «Словарь PATRICIA»

Результат работы включает библиотеку на C++, консольный словарь, воспроизводимые проверки и замеры, исходники отчёта на LaTeX и собранный PDF. Условия задают поведение словаря и содержание исследования. Представление дерева, среда macOS и методика замеров выбраны для этой работы. [Условие словаря](PATRICIA.md) · [Задание на исследование](CONTEXT.md) · [План выполнения](PLAN.md)

## Контракт словаря

Ключ состоит из букв английского алфавита, его длина до 256 символов. Регистр букв не влияет на поиск, вставку и удаление. Значение принадлежит диапазону `uint64_t` от `0` до `18446744073709551615` включительно. Верхняя граница равна 2⁶⁴ − 1. Несколько ключей могут иметь одинаковое значение. Лимиты задачи составляют 15 секунд и 512 МБ. [Условие и ограничения](PATRICIA.md)

Программа читает по одной команде из стандартного ввода до EOF и пишет по одной строке ответа в стандартный вывод. Для файлового ввода и вывода можно перенаправить потоки из `input.txt` и в `output.txt`. Регистр нормализуется только у ключа. [Протокол команд](PATRICIA.md)

| Команда | Результат |
| --- | --- |
| `+ word 34` | Новый ключ получает значение `34`, ответ `OK`. Для существующего ключа ответ `Exist`, прежнее значение сохраняется. |
| `- word` | Удаление существующего ключа даёт `OK`. Для отсутствующего ключа ответ `NoSuchWord`. |
| `word` | Для найденного ключа ответ вида `OK: 34` с его значением в десятичной записи. Для отсутствующего ключа ответ `NoSuchWord`. |
| `! Save /path/to/file` | Словарь сохраняется в компактном бинарном виде. После успешного завершения записи ответ `OK`. |
| `! Load /path/to/file` | Данные из файла заменяют весь словарь. Ответ при успехе `OK`. Загрузка отсутствующего файла или файла длиной ноль также успешна и даёт пустой словарь. |

При системной ошибке любой операции программа выводит `ERROR:` и описание на английском языке. При ошибке чтения или несовместимом формате файла команда загрузки выдаёт такую же диагностику и сохраняет прежний словарь. Ошибку доступа к существующему файлу следует отличать от отсутствия файла. [Обработка ошибок и примечание к Load](PATRICIA.md)

## Реализация библиотеки

- Библиотека предоставляет вставку пары, удаление и поиск по ключу, сохранение и загрузку. Разбор команд и печать ответов выполняет консольная программа. Обе части используют один экземпляр словаря в течение сеанса.
- Использовать двоичную PATRICIA с обратными ссылками. Каждому ключу соответствует один узел с полным ключом в нижнем регистре, значением, индексом проверяемого бита и двумя ссылками для битов 0 и 1. У служебной головы индекс `-1`. Её входная ссылка в пустом словаре ведёт на саму голову. На нисходящем переходе индекс строго возрастает. Переход к узлу с меньшим или равным индексом завершает поиск. Сюда входит ссылка узла на себя. [Алгоритмы поиска, вставки и удаления в PatriciaST](https://github.com/kevin-wayne/algs4/blob/master/src/main/java/edu/princeton/cs/algs4/PatriciaST.java)
- Для этой реализации биты нумеруются от начала строки, в каждом байте от старшего к младшему. За концом ключа все биты считаются нулевыми. Так различаются `a` и `aa`, поскольку допустимые буквы имеют ненулевой код ASCII. Поиск начинается с входной ссылки головы. После завершающего перехода сравнить ключ кандидата целиком. Попадание в голову означает промах. [Допустимые ключи](PATRICIA.md)
- При вставке дубликата вернуть `Exist`. Для нового ключа найти первый бит, отличающий его от кандидата. Для головы использовать последовательность нулевых битов. Повторным спуском найти место для этого индекса и вставить один узел. Ссылка по биту нового ключа ведёт на него самого, другая сохраняет прежнюю цель перехода. [Схема вставки](https://github.com/kevin-wayne/algs4/blob/master/src/main/java/edu/princeton/cs/algs4/PatriciaST.java)
- При удалении запомнить узел, из которого сделан завершающий переход. Если это сам удаляемый узел, заменить входящую в него нисходящую ссылку его второй ссылкой. Если переход пришёл из другого узла, исключить этот узел из прежней позиции, направив его входящую нисходящую ссылку на вторую ветвь. Затем переставить его на место удаляемого узла с индексом и связями этой позиции, сохранив собственные ключ и значение. Освободить удаляемый узел после перенаправления ссылок. [Два случая в методе delete](https://github.com/kevin-wayne/algs4/blob/master/src/main/java/edu/princeton/cs/algs4/PatriciaST.java)
- При сохранении перечислять узлы по нисходящим ссылкам. Каждую пару записывать ровно один раз, голову пропускать. При загрузке восстанавливать временное дерево вставками и заменять рабочее дерево вместе с его головой после успешного чтения. При очистке освобождать каждый узел ровно один раз. [Требования к Save и Load](PATRICIA.md)

### Бинарный формат

`Save` записывает восемь ASCII-байтов `PATRICIA`, затем пары подряд без разделителей. Каждая запись содержит длину ключа в виде `uint16_t`, от 1 до 256 байтов ключа и значение в виде `uint64_t`. Длина занимает 2 байта, значение занимает 8 байтов. Оба числа записываются в порядке little-endian.

После сигнатуры `Load` читает записи до EOF перед первым байтом очередной длины. Файл, содержащий только сигнатуру, даёт пустой словарь. Неверная или неполная сигнатура, длина вне диапазона от 1 до 256, обрыв внутри записи и ошибка чтения дают `ERROR:` и сохраняют прежний словарь. Если файл укорочен на одну или несколько целых последних записей, `Load` успешно загрузит оставшиеся записи.

## Проверка и исследование

Перед замерами словарь должен пройти проверки через консольный интерфейс на команды, границы данных, полную замену и сохранение состояния при ошибке загрузки. Случайную последовательность команд с фиксированным seed нужно сверить с независимым эталонным словарём, сравнивая каждую строку вывода. Прошедшую проверки версию и команды сборки фиксируют как точку отсчёта. Конкретные сценарии приведены в [плане](PLAN.md).

Для исследования приняты следующие параметры. Числа задают дизайн эксперимента. Нормативные лимиты приведены отдельно в условии задачи. [Задание на исследование](CONTEXT.md) · [Лимиты задачи](PATRICIA.md)

| Что фиксируем | Согласованная методика |
| --- | --- |
| Среда | Один Mac. Записать модель, объём памяти, версии macOS и компилятора, флаги сборки и идентификатор версии программы. |
| Данные | Наборы на 1 000, 10 000 и 100 000 ключей. Отдельно случайные слова и слова с длинным общим префиксом. Сохранять seed и входные файлы. |
| Нагрузки | Вставка, успешный поиск, безуспешный поиск, удаление, смешанный поток, сохранение и загрузка. Одинаковые входы для всех сравниваемых версий. |
| Измерения | Пять запусков оптимизированной сборки на сценарий, каждый в отдельном процессе. Время по монотонным часам, пиковая резидентная память по `ru_maxrss` из `os.wait4`. Для macOS перевести байты в МиБ делением на 1 048 576. Сохранить каждый результат, в сводке дать медианы и разброс. |
| Границы измерения | Генерация входов заканчивается до старта таймера. Для каждого сценария указать, включены ли запуск процесса, заполнение дерева, обработка команд и файловый ввод-вывод. |
| Диагностика | Снять профиль CPU через `sample` на длительной нагрузке. Отдельно проверить работу с памятью через AddressSanitizer и `leaks`. Для сравнения времени использовать обычную оптимизированную сборку. |

## Отчёт и приёмка

Отчёт оформляется на русском языке по шаблону МАИ. В него входят постановка задачи, описание реализации, примеры запуска, дневник, методика и результаты измерений, выводы о недочётах и полученном опыте. Дневник ведут с первой сборки. Каждая запись содержит дату, действие, инструмент, результат и принятое решение. [Шаблон LaTeX](https://github.com/toshunster/MAI-da/tree/master/report_pattern) · [Обязательное содержание отчёта](CONTEXT.md)

Для подтверждённого дефекта сохраняют воспроизводящий вход. После исправления повторяют проверки и замеры, приводят показатели исходной и исправленной версий на одинаковых данных. Если исследование не выявило повода для правок, в выводах перечисляют проведённые проверки и их результаты. Для сдачи должны собираться словарь и PDF, а каждое число в таблице должно иметь ссылку на версию программы, вход и протокол запуска. [Требования к исследованию и сравнению](CONTEXT.md)

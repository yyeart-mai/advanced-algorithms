# План выполнения лабораторной работы «Словарь PATRICIA»

Работа проходит на одном Mac. Сначала нужно получить проверенный словарь и сохранить его исходную версию. Затем на воспроизводимых данных исследовать время и память. Дневник вести с первой сборки. Контракт команд, параметры эксперимента и требования к сдаче собраны в [спецификации](SPEC.md).

## Этап 1. Подготовить отчёт и дневник

1. Разместить в `lab1` исходники LaTeX-шаблона МАИ. Включить в отчёт дневник с полями «Дата», «Действие», «Инструмент или команда», «Результат», «Решение». [Шаблон](https://github.com/toshunster/MAI-da/tree/master/report_pattern) · [Требования к дневнику](CONTEXT.md)
2. Собрать пробный PDF и проверить кириллицу, таблицу и листинг. Штатная команда `make pdf` вызывает `pdflatex`. Если локального pdfLaTeX нет, использовать среду с pdfLaTeX и записать способ сборки. [Makefile шаблона](https://github.com/toshunster/MAI-da/blob/master/report_pattern/Makefile)
3. Занести в дневник модель Mac, объём памяти, версии macOS и компилятора. По мере работы добавлять фактические команды сборки и запуска.

**Готово, когда** PDF открывается, текст и листинг читаемы, первая запись дневника позволяет повторить сборку.

## Этап 2. Реализовать библиотеку и консольную программу

1. Реализовать служебную голову и единый тип узла PATRICIA с ключом, значением, индексом бита и двумя ссылками. Разобрать на ключах `a` и `aa` нормализацию, чтение битов за концом слова и поиск до первой ссылки, на которой индекс перестаёт расти. Сравнить полный ключ найденного кандидата. [Устройство дерева](SPEC.md)
2. Реализовать вставку узла на первом различающемся бите. Для удаления разобрать на схеме оба случая: поиск завершился ссылкой на себя или обратной ссылкой из другого узла. В обоих случаях проследить путь к каждому оставшемуся ключу после перенаправления ссылок. [Алгоритмы вставки и удаления](SPEC.md)
3. Подключить библиотеку к консольной программе. Проверить точные ответы на вставку, повторную вставку в другом регистре, запрос значения и удаление. [Протокол](PATRICIA.md)
4. Реализовать `Save` обходом по нисходящим ссылкам, а `Load` чтением записей до EOF и вставкой пар во временный словарь. При замене и уничтожении дерева проверить время жизни головы и однократное освобождение узлов. [Бинарный формат](SPEC.md#бинарный-формат)

**Готово, когда** программа собирается, обрабатывает все пять команд до EOF, а файл, сохранённый одним процессом, читается другим.

## Этап 3. Проверить корректность и сохранить исходную версию

| Проверка через консоль | Что сверить |
| --- | --- |
| Пустое дерево, удаление последнего ключа и повторное удаление | Ответы на поиск и удаление, возможность снова вставить ключ. |
| Вставить `a` и `aa` с разными значениями. В одном прогоне первым удалить `aa`, в другом первым удалить `a` | Покрыты удаление по самоссылке и удаление по обратной ссылке из другого узла. После каждого удаления проверить значение оставшегося ключа, затем повторно вставить удалённый. |
| Повторная вставка в другом регистре, два слова с одинаковым значением | Дубликат даёт `Exist`, первое значение сохраняется. Удаление одного слова сохраняет другое. |
| `a` и `aa`, ключи длиной 256 букв с различием в конце, значения `0` и `18446744073709551615` | Оба ключа доступны независимо, граничные значения возвращаются точно. |
| Загрузка сохранённого словаря в новом процессе и поверх другого словаря | Все сохранённые пары восстановлены, прежние посторонние ключи исчезли. |
| Загрузка в непустое дерево из пустого файла, отсутствующего файла и файла только с сигнатурой | Во всех случаях ответ `OK`, прежний ключ исчез. |
| Неверная или неполная сигнатура, недопустимая длина, обрыв внутри длины, ключа или значения, ошибка доступа | Ответ начинается с `ERROR:`, пояснение дано на английском. После неудачной загрузки прежний ключ доступен с исходным значением. |
| Файл укорочен ровно на последнюю запись | Ответ `OK`, загружены все оставшиеся пары. |
| Поток случайных операций с фиксированным seed | Каждая строка вывода совпадает с ответом независимого эталонного словаря. |

В отладочной сборке после вставок, удалений и загрузки проверить инварианты. Обход по нисходящим ссылкам должен посетить каждый узел данных ровно один раз. Поиск ключа каждого посещённого узла должен завершиться на этом же узле. После удаления последнего ключа входная ссылка головы должна вести на неё саму.

**Готово, когда** проверки проходят через обычную точку входа, сохранены команды повторного запуска и зафиксирована ревизия исходной версии до профилирования. [Условие для ожидаемых ответов](PATRICIA.md) · [Цель сравнения версий](CONTEXT.md)

## Этап 4. Измерить время и память

1. Подготовить входы для вставки, успешного и безуспешного поиска, удаления, смешанного потока, `Save` и `Load`. Для каждого размера и типа ключей из спецификации сохранить вход, seed и число операций. Для загрузки заранее подготовить файл словаря.
2. Запустить каждый сценарий пять раз в отдельных процессах на оптимизированной сборке с одинаковыми флагами. Измерить время монотонными часами и пиковую память дочернего процесса через `os.wait4`. Сохранить для каждого запуска версию, вход, границы измерения, время, память и код завершения. Свести результаты в таблицу медиан и разброса. [Матрица эксперимента](SPEC.md)
3. Профилировать длительный сценарий через `sample`. Зафиксировать команду, нагрузку и функции, в которых наблюдается наибольшее число выборок. Отдельно запустить проверки памяти с AddressSanitizer и `leaks`, включая оба случая удаления, многократную замену дерева при загрузке и выход из программы с непустым словарём. Сохранить диагностические протоколы. [Допустимые средства исследования](CONTEXT.md)

**Готово, когда** для исходной версии есть сырые результаты всех повторов, сводная таблица, профиль CPU и протоколы проверки памяти.

## Этап 5. Разобрать результаты и сдать отчёт

1. Для каждого подтверждённого недочёта записать вход, наблюдаемый симптом и предлагаемую правку. После внесения исправления повторить функциональные проверки и тот же эксперимент. Сопоставить результаты с учётом разброса повторов. Если оснований менять код нет, описать этот результат и проведённые проверки. [Требования к выводам и сравнению](CONTEXT.md)
2. Перенести в отчёт описание дерева, примеры реальных запусков, методику, таблицы, результаты диагностики и выводы. Для каждого показателя указать версию, вход и протокол. Лимиты задачи приводить отдельно от локальных замеров. [Условие](PATRICIA.md) · [Структура шаблона](https://github.com/toshunster/MAI-da/blob/master/report_pattern/report.tex)
3. По сохранённым командам повторно собрать словарь и финальный PDF. Открыть PDF, проверить титульный лист, кириллицу, листинги, таблицы и отсутствие текста-примера из шаблона.

**Готово к сдаче, когда** словарь и PDF собираются из сохранённых исходников, проверки проходят, дневник отражает ход работы, а числа и выводы в отчёте прослеживаются до конкретных запусков.

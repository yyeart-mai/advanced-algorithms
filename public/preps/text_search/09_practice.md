# Практика

Задания составлены для этого конспекта. Сначала сформулируй решение, оцени время и память, выпиши граничные случаи. Потом раскрывай разбор. Код для сравнения указан в каждом задании. Обозначения совпадают с [главной страницей](README.md).

## 1. Все вхождения с перекрытием

Напиши поиск всех начал непустого образца. Проверь `aa` в `aaaa`, `abc` в `ab`, `x` в пустом тексте, `a b` в `a b a b`. Сначала реши перебором, затем KMP.

<details>
<summary>Подсказка</summary>

После совпадения не пропускай всё найденное вхождение. В KMP сохрани границу образца.

</details>

<details>
<summary>Разбор</summary>

Ответы по прямой проверке отрезков: `0, 1, 2`, пустой список, пустой список, `0, 4`. Для KMP после успеха нужен `j = pi[m - 1]`. Сравни [перебор](code/01_naive.cpp) и [KMP](code/04_kmp.cpp). Общая оценка KMP `O(m + n + z)`, память `O(m)` без входа и ответа.

</details>

## 2. Вычисление массивов вручную

Найди `pi` и Z для `aaaaa` и `abacaba`, считая `z[0] = 0`. Для каждого ненулевого числа покажи совпавшие отрезки.

<details>
<summary>Подсказка</summary>

`pi[i]` относится к концу префикса, `z[i]` к началу совпадения с префиксом всей строки.

</details>

<details>
<summary>Разбор</summary>

```text
aaaaa:
pi = 0 1 2 3 4
z  = 0 4 3 2 1

abacaba:
pi = 0 0 1 0 1 2 3
z  = 0 0 1 0 3 0 1
```

Числа получаются сравнением начал и концов префиксов для `pi`, сравнением начала всей строки с каждой позицией для Z. Сверка: [prefixFunction](code/02_prefix.cpp) и [zFunction](code/03_z.cpp). Чтобы вызвать вторую для отдельной строки, переведи её байты в `vector<int>`.

</details>

## 3. Все границы и кратчайший блок

Для непустой строки выведи длины всех непустых собственных границ по возрастанию. Затем найди кратчайший блок, повторением которого получается вся строка. Проверь `ababa` и `ababab`.

<details>
<summary>Подсказка</summary>

Иди по цепочке `pi[m - 1]`, `pi[b - 1]`. Период и длина повторяющегося блока совпадают только при нужной делимости.

</details>

<details>
<summary>Разбор</summary>

Построй `pi`, собери цепочку границ, разверни массив. У `ababa` границы 1 и 3, у `ababab` 2 и 4. Поиск периода: `p = m - pi[m - 1]`. Если `m % p == 0`, кратчайший блок есть префикс длины `p`, иначе вся строка. Для `ababa` результат `ababa`, для `ababab` результат `ab`. Формула обоснована в [главе о префикс-функции](02_prefix_and_kmp.md). Время `O(m)`, память `O(m)`.

</details>

<details>

</details>

<details>

## 6. Сдвиги Бойера и Мура

Для `P = abcd` и окна `abxd` найди позицию несовпадения и сдвиг плохого символа. Для `P = ababa` найди сдвиг после успеха. Почему для `a^m` в `a^n` приведённый код не имеет линейной оценки поиска всех совпадений?

<details>
<summary>Подсказка</summary>

Используй `max(1, j - last[c])`, затем границу всего образца. Посчитай повторные сравнения после каждого успеха.

</details>

<details>
<summary>Разбор</summary>

В первом случае `j = 2`, `last[x] = -1`, сдвиг равен 3. Во втором граница длины 3, сдвиг `5 - 3 = 2`. Для одних `a` после успеха сдвиг равен 1, а код повторяет все `m` сравнений. Их число `(n - m + 1)m` при `m <= n`. Разбор обоих правил и препроцессинга: [глава 4](04_realtime_and_boyer_moore.md), [код](code/06_boyer_moore.cpp).

</details>

## 7. Удаление слова, которое является префиксом

Вставь `car`, `cart`, `cat`, удали `car`. Проверь `car`, `cart`, `ca`, `cat`. Нарисуй обычный и compact trie до и после удаления.

<details>
<summary>Подсказка</summary>

Удаляется отметка конца слова. Сжатие допустимо только для нетерминальной вершины с одним ребёнком.

</details>

<details>
<summary>Разбор</summary>

Ответы: `NO`, `YES`, `NO`, `YES`. В compact trie до удаления из пути `ca` выходят `r` с отметкой конца `car` и ребёнком `t`, а также `t` с отметкой конца `cat`. После снятия отметки вершина после `r` сжимается, получается ребро `rt` к концу `cart`. [Обычный trie](code/07_trie.cpp), [compact trie](code/08_compact_trie.cpp).

</details>

## 8. Терминальные суффиксы и дубликаты

<details>

Сначала выдаётся текущая вершина, затем терминальные суффиксы. Два одинаковых образца имеют разные номера.

</details>

<details>

```text

```

После последнего байта текущая вершина `she` даёт номер 1 с началом 0. Выходная ссылка ведёт в `he`, там номера 0 и 3 с началом 1. Следующая ведёт в `e`, номер 2 с началом 2. Это прямой обход `exit` из [программы](code/09_aho_corasick.cpp).

## 9. Только количество каждого образца

Измени алгоритм Ахо и Корасика так, чтобы получать количество вхождений каждого образца без перечисления всех совпадений. Образцы могут повторяться. Нужна оценка `O(L + vσ + k + n)`.

<details>
<summary>Подсказка</summary>

Во время прохода считай посещения текущих состояний. Ответы распространяются от длинных путей к их суффиксам.

</details>

<details>
<summary>Разбор</summary>

Сохрани порядок BFS при построении. Во время поиска выполняй только переход и `count[v]++`. Затем пройди все некорневые вершины в обратном порядке BFS и выполни `count[link[v]] += count[v]`. Для каждого номера образца возьми счётчик его терминальной вершины. Пустые образцы остаются проигнорированными, как в исходном интерфейсе.

Почему верно: после каждого байта текущая вершина соответствует самому длинному подходящему суффиксу. Все более короткие подходящие суффиксы лежат на её цепочке `link`. Перенос счётчиков по дереву ссылок учитывает это окончание у всех его предков. Обратный BFS гарантирует, что накопление от потомков закончится до переноса из родителя. Каждый вклад проходит каждое ребро дерева ссылок через сумму счётчиков, а не отдельной операцией на каждое вхождение.

Построение `O(L + vσ + k)`, проход текста `O(n)`, перенос `O(v)`, выдача `O(k)`. Дополнительные массивы требуют `O(v + k)`. Для образцов `a`, `aa`, `a` в `aaaa` ответы `4, 3, 4`, что получается подсчётом допустимых начал каждого образца. Основа для изменения: [класс автомата](code/09_aho_corasick.cpp).

</details>

Построй суффиксное дерево `banana`. Найди `ana`, `ban`, `na`, `ann`. В каких запросах образец заканчивается внутри ребра? Как ответить только `YES` или `NO`, без сбора листьев?

<details>
<summary>Подсказка</summary>

</details>

<details>
<summary>Разбор</summary>

Ответы по начальным позициям: `1, 3`, затем `0`, затем `2, 4`, затем пустой список. `ban` заканчивается внутри ребра `banana$`. Успешный проход всех символов означает `YES`, даже если вершина ещё не достигнута. Для проверки существования время запроса `O(m)` при фиксированном алфавите. </details>

## 11. Размер ответа

Текст состоит из 100000 букв `a`, образцы `a`, `aa`, ..., строка из 1000 букв `a`. Сколько пар придётся вывести? Нужно ли перечислять их, если задача просит только количество для каждого образца?

<details>
<summary>Подсказка</summary>

Для длины `d` число начал равно `n - d + 1`. Сложи арифметическую прогрессию.

</details>

<details>
<summary>Разбор</summary>

Число совпадений равно `1000 * 100001 - 1000 * 1001 / 2 = 99500500`. Первое произведение получается из суммы постоянной части `n + 1`, второе есть сумма длин от 1 до 1000. На вывод почти ста миллионов пар нужно время хотя бы пропорциональное их количеству. Для одних счётчиков используй перенос по суффиксным ссылкам из задания 9 и не создавай массив пар. Огромный размер ответа нельзя убрать заменой одного алгоритма перечисления другим.

</details>

## 12. Контрольный выбор алгоритма

Для каждой ситуации выбери подход и назови ограничение, которое ещё надо проверить:

1. Один длинный образец, текст поступает частями, память ограничена.
2. Много образцов, один текст, надо получить все вхождения.
3. Есть команды добавления, удаления и проверки целого слова.
4. Один текст, много запросов, учебное суффиксное дерево строится вставкой всех суффиксов.
5. В задаче явно требуется Бойер и Мур.

<details>
<summary>Разбор</summary>

1. Обычный KMP, сохраняем `j` между частями и общий индекс. Проверяем размер образца и тип индексов. Не нужно склеивать и хранить текст.
2. Ахо и Корасик. Проверяем память полной таблицы `v * 256` и размер выдачи `z`.
3. Trie. Уточняем, множество это или мультимножество, и надо ли освобождать память удалённых слов.
4. Суффиксное дерево подходит по интерфейсу запросов, но сначала проверяем допустимость `O(n²)` построения. Само число запросов не делает квадратичный этап дешёвым.
5. Используем оба правила из [главы 4](04_realtime_and_boyer_moore.md), если условие не задаёт другой вариант. Проверяем требования к выводу и оценку конкретной реализации.

Сравнение подходов и оценки: [таблица выбора](README.md).

</details>

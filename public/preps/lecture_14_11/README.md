# Лекция 14.11: алгоритм Укконена и приложения суффиксного дерева

В [лекции 7.11](../lecture_07_11/README.md) дерево строится наивной вставкой всех суффиксов. Здесь [ukkonen_tree.hpp](ukkonen_tree.hpp) содержит общее ядро алгоритма Укконена. Оно хранит активную точку, суффиксные ссылки и общий растущий конец рёбер листьев. Уникальный терминатор делает каждый суффикс отдельным листом. Конструктор получает строку целиком и обрабатывает её символы слева направо. Потокового интерфейса для добавления символов после создания объекта здесь нет.

Для байтовой строки используется простой `UkkonenTree`, который кодирует байты числами от 0 до 255 и добавляет терминатор 256. Шаблонный `UkkonenIndex<Symbol, Compare>` принимает входные итераторы и кодирует произвольные сравнимые символы. Файлы `.cpp` ниже являются самостоятельными программами C++17 и подключают общий заголовок.

| Файл | Ввод | Вывод |
| --- | --- | --- |
| [ukkonen.cpp](ukkonen.cpp) | Текст и непустой образец, по одной строке | Все начальные позиции образца в порядке возрастания |
| [generalized_suffix_tree.cpp](generalized_suffix_tree.cpp) | Две строки | Длина наибольшей общей подстроки и сама подстрока |
| [matching_statistics.cpp](matching_statistics.cpp) | Сначала опорный текст, затем запрос | Для каждой позиции запроса пара `длина позиция_в_тексте` |

Все позиции начинаются с нуля. Варианты для строк сравнивают байты, поэтому позиции в UTF-8 тоже измеряются в байтах. Для пустого образца `ukkonen.cpp` ничего не выводит. При нескольких наибольших общих подстроках выбирается та, которая начинается раньше в первой строке. Для статистики совпадений выбирается самая ранняя позиция в опорном тексте. Если совпадения нет, программа выводит `0 -1`.

## Что делают приложения

Обобщённое дерево строится для `A + разделитель_1 + B + разделитель_2`. Оба разделителя отличаются друг от друга и от символов строк. Листья помечаются по строке, в которой начинается суффикс. Самая глубокая вершина, под которой есть листья обеих строк, задаёт наибольшую общую подстроку. Код показывает простой вариант для байтовых строк и шаблонную функцию `longestCommonSubstringGeneric` для диапазонов других типов. [Конспект Хельсинкского университета](https://www.cs.helsinki.fi/u/tpkarkka/teach/14-15/SPA/all-lectures.pdf) выводит этот способ через глубину и метки листьев.

Статистика совпадений для запроса `Q` относительно текста `T` содержит для каждого `i` длину наибольшего префикса `Q[i..]`, который встречается в `T`, и позицию одного его вхождения. В коде возвращается самая ранняя позиция. Простая и шаблонная версии заново проходят по дереву для каждого суффикса запроса. Это даёт `O(|Q|²)` времени в худшем случае после построения дерева. [Тот же конспект](https://www.cs.helsinki.fi/u/tpkarkka/teach/14-15/SPA/all-lectures.pdf) описывает также линейный вариант со следованием по суффиксным ссылкам.

Построение дерева через `UkkonenTree` занимает `O(n)` времени и памяти для фиксированного байтового алфавита. Переходы здесь хранятся в `std::map`, поэтому для произвольного алфавита поиск перехода добавляет множитель `O(log σ)`. [Исходная статья Укконена](https://cs.brown.edu/courses/csci1820/spring-2022/resources/Ukkonen_1995.pdf) описывает обработку строки слева направо и линейную оценку при подходящей модели алфавита.

Проверяемые примеры:

```text
ukkonen.cpp:                 banana / ana    -> 1, 3
generalized_suffix_tree.cpp: banana / ananas -> 5, anana
matching_statistics.cpp:    banana / ana    -> (3, 1), (2, 2), (1, 1)
```

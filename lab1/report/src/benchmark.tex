\subsection{Методика замеров}

Для замеров использовалась оптимизированная сборка словаря (Apple Clang~21.0.0). Замеры проходили на MacBook Pro с Apple M5 и 16~ГБ памяти под macOS~26.7.3.

Размер набора \(N\) составлял 1\,000, 10\,000 или 100\,000 ключей по 32 буквы. Для каждого размера подготовлены два набора. В первом все ключи случайны. Во втором первые 24 буквы каждого ключа заменены общим префиксом, а последние восемь букв, значения и порядок вставки сохранены. Ключи для вставки генерировали с seed~42, а ключи для безуспешного поиска с seed~43.

Каждый из семи сценариев запускался пять раз в отдельном процессе для каждого размера и типа ключей, всего \(7 \times 3 \times 2 \times 5 = 210\) запусков. Время измеряли от запуска программы до её завершения, включая чтение команд и запись ответов. Входные данные готовились заранее, ответы сверялись после остановки таймера. В столбцах «Память» указано, сколько оперативной памяти занимала программа на пике за время работы (в МиБ).

В сценарии вставки словарь получал \(N\) новых ключей. Сценарии поиска, удаления и смешанной нагрузки начинались с тех же \(N\) вставок, за которыми следовали \(N\) команд. В смешанном сценарии чередовались вставка, успешный поиск, поиск отсутствующего ключа и удаление. Замер \texttt{Save} включал заполнение словаря и запись нового файла. При замере \texttt{Load} пустой словарь читал заранее подготовленный файл.

\subsection{Профилирование поиска}

После 100\,000 вставок словарь получил 60 блоков по 100\,000 успешных запросов к ключам с общим префиксом. Команды поступали через канал, ответы отбрасывались. Через секунду после запуска утилита \texttt{sample} начала записывать стеки вызовов с интервалом 1~мс. Запись длилась три секунды.

В 2\,097 из 2\,565 выборок главного потока (81,8\,\%) в стеке присутствовало чтение очередной команды. Метод поиска \texttt{Patricia::find} оказался на вершине стека в 214 выборках.

\subsection{Проверка памяти}

Сборка с AddressSanitizer прошла тесты словаря, включая 20\,000 смешанных команд с seed 20261120. Ответ на каждую команду этой серии сверялся с эталонным словарём.

Утечки проверялись отдельно утилитой \texttt{leaks}. Сценарий из 21 команды включал оба случая удаления, двукратную замену дерева при загрузке и выход из программы с тремя ключами. Все ответы совпали с ожидаемыми. Утилита проверила 189 выделенных блоков и сообщила о нуле утечек.

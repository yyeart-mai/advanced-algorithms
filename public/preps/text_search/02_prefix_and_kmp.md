# Префикс-функция и KMP

## Префикс-функция

`pi[i]` есть длина наибольшей границы строки `s[0:i+1)`. Вся строка границей не считается, поэтому `pi[0] = 0`. Например, у `ababa` наибольшая граница `aba`, следовательно, `pi[4] = 3`. Определение и реализация находятся в [02_prefix.cpp](code/02_prefix.cpp).

Вычислим массив для `ababaca`:

```text
i       0 1 2 3 4 5 6
s[i]    a b a b a c a
pi[i]   0 0 1 2 3 0 1
```

Каждое число есть длина совпавших начала и конца соответствующего префикса. Например, у `ababa` граница `aba` даёт 3, у `ababac` непустой границы нет, получается 0.

## Откуда берётся переход `j = pi[j - 1]`

Допустим, уже известна граница длины `j = pi[i - 1]`. Если `s[i] == s[j]`, её можно продлить на один символ. Если символы различаются, граница длины `j + 1` не подходит.

Следующий кандидат обязан быть границей уже совпавшего префикса `s[0:j)`. Длина его самой длинной границы есть `pi[j - 1]`. Поэтому прыгаем сразу туда. Остальные возможные границы лежат в этой же цепочке. Перебирать все промежуточные длины не нужно: они не удовлетворяют условию совпадения начала и конца.

Разбор позиции `i = 5` в `ababaca`:

1. `j = pi[4] = 3`, сравниваем `c` с `s[3] = b`, несовпадение.
2. `j = pi[2] = 1`, сравниваем `c` с `s[1] = b`, несовпадение.
3. `j = pi[0] = 0`, сравниваем `c` с `s[0] = a`, несовпадение.
4. Продлить ничего нельзя, `pi[5] = 0`.

Сохраняем именно длину границы, поэтому индекс следующего символа равен `j`, а индекс последнего символа уже совпавшей части равен `j - 1`.

## Почему вычисление линейное

Во внешнем цикле длина кандидата увеличивается не более чем на единицу за позицию. Каждая итерация `while` строго уменьшает её. При переходе к следующей позиции начальный кандидат равен только что вычисленному значению. Значит, суммарное число уменьшений ограничено суммарным числом увеличений, то есть `O(|s|)`. Добавляем по одной проверке на позицию и получаем линейное время. Массив занимает `O(|s|)` памяти. Это амортизированная оценка, внутренний цикл сам по себе её не опровергает.

## KMP: применяем границы к поиску

Построим `pi` только для образца. При чтении текста храним `j`, длину совпавшего префикса образца. Перед следующим байтом `j < m`, поскольку после полного совпадения мы сразу выполняем откат. [Полная программа](code/04_kmp.cpp).

Для очередного `T[i]`:

1. Пока `j > 0` и `T[i] != P[j]`, присваиваем `j = pi[j - 1]`.
2. Если `T[i] == P[j]`, увеличиваем `j`.
3. Если `j == m`, нашли вхождение с началом `i - m + 1`.
4. После успеха ставим `j = pi[m - 1]`, сохраняя возможность перекрытия.

Инвариант после обработки байта до отката полного совпадения: `j` есть длина наибольшего префикса образца, являющегося суффиксом прочитанного текста. При несовпадении цепочка границ перебирает все возможные более короткие кандидаты. Текст назад не перемещается. Подход к линейному поиску через информацию о префиксах описан в [исходной статье Кнута, Морриса и Пратта](https://www.cs.jhu.edu/~misha/Spring23/Knuth77.pdf).

Пример `P = aba`, `pi = [0, 0, 1]`, `T = ababa`:

| `i` | Байт | `j` до | `j` после сравнения | Действие |
| --- | --- | --- | --- | --- |
| 0 | a | 0 | 1 | продолжить |
| 1 | b | 1 | 2 | продолжить |
| 2 | a | 2 | 3 | вывести 0, откатить к 1 |
| 3 | b | 1 | 2 | продолжить |
| 4 | a | 2 | 3 | вывести 2, откатить к 1 |

Откат к нулю после первого успеха потерял бы вхождение с начала 2. Формула начала получается из того, что последний индекс равен `i`, а длина совпадения равна `m`.

Подготовка занимает `O(m)`. При поиске `j` увеличивается не более `n` раз, а откаты его уменьшают. Итого `O(n + z)` для прохода и выдачи ответов. Память `O(m)` без входа и ответа. Образец и `pi` можно хранить, а текст читать по байту.

## Границы и периоды

У строки длины `m` все непустые границы можно перечислить цепочкой `b = pi[m - 1]`, затем `b = pi[b - 1]`, пока `b > 0`.

Период `p` означает `s[i] == s[i - p]` для всех `p <= i < m`. Это равносильно границе длины `m - p`. Поэтому кратчайший период непустой строки равен `p = m - pi[m - 1]`. Здесь период не обязан укладываться целое число раз: у `ababa` период 2, хотя длина 5 не делится на 2. Для представления строки как нескольких одинаковых блоков дополнительно проверяют `m % p == 0`.

Эти формулы следуют из сравнения отрезков `s[p:m)` и `s[0:m-p)`, то есть непосредственно из определения границы. Пример для проверки: у `ababab` последнее `pi` равно 4, период `6 - 4 = 2`, число блоков `6 / 2 = 3`.

## Где ошибаются

- Вместо `pi[j - 1]` используют `pi[j]`. Это другой префикс, переход может не уменьшать кандидата.
- После отката сразу читают следующий байт текста. Текущий байт ещё надо сравнить с новым кандидатом.
- После успеха оставляют `j == m`. Тогда следующее обращение к `P[j]` выходит за границу.
- Смешивают длину границы и индекс её последнего символа.

Перед переходом дальше восстанови KMP по четырём шагам без подглядывания в код.

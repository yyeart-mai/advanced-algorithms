# Лекция 7.11: поиск подстроки и суффиксное дерево

## Ахо и Корасик

[aho_corasick.cpp](aho_corasick.cpp) ищет несколько образцов за один проход по тексту. Простая версия работает с байтовыми строками и полной таблицей переходов. Шаблонная версия принимает образцы и текст через итераторы, хранит переходы в `std::map` и выдаёт совпадения через выходной итератор. Для шаблонной версии сначала вызываются `addPattern` и `build`, затем `search`.

Ввод: число образцов `k`, затем `k` строк с образцами и одна строка текста. Пустые образцы игнорируются, остальные нумеруются с нуля в порядке ввода. Каждая строка вывода содержит `позиция номер_образца`. Совпадения идут по позиции окончания в тексте, при одинаковом окончании по номеру образца. Повторяющиеся образцы сохраняются как разные номера.

Пример ввода:

```text
2
aba
ba
ababa
```

Вывод:

```text
0 0
1 1
2 0
3 1
```

Полная таблица простой версии занимает `O(256v)` памяти, где `v` равно числу вершин. К ней добавляется память для списков совпадающих образцов в вершинах. Обработка текста после построения автомата требует `O(n + z)` времени, где `z` равно числу выведенных совпадений. [Исходная статья Ахо и Корасик](https://par.cse.nsysu.edu.tw/resource/paper/2022/220913/Efficient%20String%20Matching%20an%20Aid%20to%20Bibliographic%20Search.pdf) описывает автомат, суффиксные переходы и однопроходный поиск.

## Суффиксное дерево

[suffix_tree.cpp](suffix_tree.cpp) строит компактное дерево всех суффиксов текста, вставляя их по одному и расщепляя ребро при несовпадении. Ребро хранит диапазон исходного текста вместо копии подстроки. Простая версия использует для конца текста отдельный символ 256, который не совпадает ни с одним байтом. Шаблонная версия использует `std::nullopt` как отдельный терминатор и принимает символы через итераторы.

Ввод: первая строка содержит текст, вторая строка содержит непустой образец. Выводятся все начальные позиции образца с нуля в порядке возрастания, по одной в строке. Для пустого образца пример ничего не выводит.

Пример ввода:

```text
banana
ana
```

Вывод:

```text
1
3
```

Построение занимает `O(n²)` времени и `O(n)` памяти при фиксированном байтовом алфавите. После прохода по пути образца программа собирает позиции из листьев и сортирует их, поэтому запрос занимает `O(m + z log z)` времени при фиксированном алфавите. Здесь `n` равно длине текста, `m` равно длине образца, `z` равно числу вхождений. [Конспект Университета Ватерлоо](https://cs.uwaterloo.ca/~plragde/flaneries/FDS/Text_Processing.html) разбирает хранение рёбер диапазонами, наивную вставку суффиксов и поиск через листья поддерева.

# Z-функция

## Что хранит массив

`z[i]` есть длина самого длинного совпадения префикса всей строки `s` с подстрокой, начинающейся в `i`. В этой папке `z[0] = 0` по соглашению. Для `abacaba`:

```text
i       0 1 2 3 4 5 6
s[i]    a b a c a b a
z[i]    0 0 1 0 3 0 1
```

Например, с позиции 4 начинается `aba`, совпадающее с первыми тремя буквами. Поэтому `z[4] = 3`. В отличие от `pi[i]`, значение относится к совпадению, которое начинается в `i`, а не заканчивается в `i`.

Определение Z, переиспользование уже найденных совпадений и поиск через объединение образца и текста разобраны в [лекции CMU о Z-алгоритме](https://www.cs.cmu.edu/~ckingsf/bioinfo-lectures/zalg.pdf). Ниже используются индексы с нуля и полуинтервалы, как в [программе](code/03_z.cpp).

## Окно `[l, r)`

Поддерживаем найденный отрезок `s[l:r)`, совпадающий с префиксом `s[0:r-l)`, с максимальной достигнутой правой границей. На очередной позиции `i` есть два случая.

Если `i >= r`, полезного окна нет. Начинаем с `z[i] = 0` и сравниваем символы напрямую.

Если `i < r`, позиция находится внутри окна. Ей соответствует позиция `i - l` в префиксе, для которой Z уже вычислено. Можно сразу взять:

```cpp
z[i] = std::min(r - i, z[i - l]);
```

Ограничение `r - i` обязательно: окно подтверждает равенство только до `r`. После инициализации продлеваем совпадение обычными сравнениями. Если `i + z[i] > r`, обновляем `l = i`, `r = i + z[i]`.

Для `abacaba` на позиции 4 сравнение даёт окно `[4, 7)`. На позиции 5 используем `z[1] = 0`, так как `5 - 4 = 1`. На позиции 6 берём `min(7 - 6, z[2]) = min(1, 1) = 1`. Все символы совпадения на позиции 6 уже известны.

## Почему это корректно и быстро

Внутри окна равенство с префиксом уже доказано предыдущими сравнениями. Если скопированное Z заканчивается раньше правой границы, известен также следующий несовпавший символ. Если оно достигает границы, всё за границей нужно проверить. Поэтому алгоритм не приписывает непроверенные совпадения.

Каждое успешное дополнительное сравнение расширяет текущую максимальную правую границу, кроме случая полностью известного короткого совпадения, где расширения нет и сразу получается несовпадение. Граница проходит строку один раз. На каждую позицию приходится не более одной неудачной проверки. Итого `O(|s|)` времени и `O(|s|)` памяти под массив. Это можно проверить по единственному расширяющему `while` в [zFunction](code/03_z.cpp).

## Поиск образца

Построим последовательность `S = P + разделитель + T`. В позиции объединённой последовательности `i >= m + 1` образец входит тогда и только тогда, когда `z[i] == m`. Начало в тексте равно `i - m - 1`: вычитаем длину образца и один разделитель.

Разделитель должен отсутствовать и в образце, и в тексте. Символ `#` не гарантирует этого для произвольного ввода. Поэтому в коде байты переводятся в `vector<int>` со значениями `0..255`, а разделитель равен `256`. Это конкретная реализация для байтовых строк, без шаблонов. Лекционная [Z-функция для string](../lecture_24_10/03_z.cpp) использует тот же алгоритм вычисления массива.

Пример с условным разделителем `#` для наглядности:

```text
P = aba
T = ababa
S = aba#ababa
индексы S: 4 6
индексы T: 0 2
```

В `S[4:]` и `S[6:]` первые три символа равны `aba`, поэтому получаем начала `4 - 3 - 1 = 0` и `6 - 3 - 1 = 2`. Реальная программа использует число 256 вместо `#`.

Длина объединения `m + 1 + n`, построение и вычисление Z линейны по этой длине. Дополнительная память `O(m + n)`. Для потокового поиска без хранения всего текста удобнее обычный KMP из предыдущей главы.

## Самопроверка

Выпиши Z для `aaaaa`. Затем объясни, почему выражение `z[i] = z[i - l]` без ограничения правой границей может перенести ещё не проверенные символы. Результат первого задания: `0 4 3 2 1`, поскольку с каждой следующей позиции остаётся на один `a` меньше.

# Подготовка к контесту «Поиск в тексте»

Самостоятельный разбор с нуля: от перебора позиций до поиска множества образцов и суффиксного дерева. Основа состава тем: [список лекций](../README.md) и [учебный контекст](../../../STUDY_CONTEXT.md). В примерах используются обычные функции и классы C++17 со `string`, `vector` и конкретными типами. Обобщённых версий с шаблонами функций и итераторами здесь нет.

## Как проходить

1. [Термины, индексы и наивный поиск](01_basics.md). Научись формулировать задачу и проверять ответ перебором.

4. [KMP реального времени и Бойер и Мур](04_realtime_and_boyer_moore.md). Таблица переходов и два правила безопасного сдвига.
5. [Trie и compact trie](05_trie.md). Основа следующих структур.
6. [Ахо и Корасик](06_aho_corasick.md). Сразу много образцов в одном тексте.

Если нужен короткий первый проход, изучи главы 1, 2, 3, 5 и 6. Затем вернись к остальным. Это порядок подготовки, а не утверждение о составе задач будущего контеста.

## Как выбрать алгоритм

Обозначения: `n` есть длина текста, `m` есть длина одного образца, `L` есть сумма длин всех образцов, `v` есть число вершин trie, `k` есть число образцов, `z` есть число выведенных совпадений. Для таблиц переходов `σ = 256`, поскольку код работает с байтами. Оценки ниже выведены в соответствующих главах по приложенному коду. Хранение входа и массива ответа не включено в дополнительную память, ответ добавляет `O(z)`.

| Задача или метод | Подготовка | Поиск | Дополнительная память |
| --- | --- | --- | --- |
| Наивный поиск | нет | `O(nm)` | `O(1)` |
| KMP, один образец | `O(m)` | `O(n + z)` | `O(m)` |
| Z-поиск, один образец | объединение за `O(n + m)` | вычисление Z и сбор за `O(n + m + z)` | `O(n + m)` |
| KMP с полной таблицей | `O(mσ)` | `O(n + z)`, один переход на байт | `O(mσ)` |
| Бойер и Мур в этой папке | `O(m + σ)` | верхняя граница `O(nm)` для всех вхождений | `O(m + σ)` |
| Словарь слов, trie на `map` | вставка слова длины `d`: `O(d log(σ + 1))` | проверка слова: столько же | `O(v)` для всех вершин и рёбер |
| Ахо и Корасик с выходными ссылками | `O(L + vσ + k)` | `O(n + z)` | `O(vσ + k)` |
| Суффиксное дерево с наивной вставкой | `O(n²)` при фиксированном алфавите | `O(m + z log(z + 1))` с сортировкой позиций | `O(n)` |

Один образец и один текст: начни с KMP или Z. Много образцов: рассматривай Ахо и Корасика. Проверка принадлежности словарю: trie. Много запросов к неизменному тексту: полезна идея суффиксного дерева, но сначала проверь допустимость квадратичного построения этой реализации.

## Код и запуск

Каждый файл из [code](code) является отдельной программой. Пример запуска из этой папки:

```sh
c++ -std=c++17 -O2 -Wall -Wextra -pedantic code/04_kmp.cpp -o /tmp/text_search_kmp
printf 'aba\nababa\n' | /tmp/text_search_kmp
```

Ожидаемый вывод, полученный сравнением `ababa[0:3]` и `ababa[2:5]` с `aba`:

```text
0
2
```

| Файл | Ввод | Вывод |
| --- | --- | --- |
| [01_naive.cpp](code/01_naive.cpp) | образец, затем текст, две строки | начальные позиции |
| [02_prefix.cpp](code/02_prefix.cpp) | одна строка | массив `pi` |
| [03_z.cpp](code/03_z.cpp) | образец, затем текст | начальные позиции через Z |
| [04_kmp.cpp](code/04_kmp.cpp) | образец, затем текст | начальные позиции |
| [05_kmp_realtime.cpp](code/05_kmp_realtime.cpp) | образец, затем текст | начальные позиции |
| [06_boyer_moore.cpp](code/06_boyer_moore.cpp) | образец, затем текст | начальные позиции |
| [07_trie.cpp](code/07_trie.cpp), [08_compact_trie.cpp](code/08_compact_trie.cpp) | число команд, затем `+ слово`, `- слово`, `? слово` | `YES` или `NO` для `?` |
| [09_aho_corasick.cpp](code/09_aho_corasick.cpp) | `k`, затем `k` строк образцов, затем текст | пары `позиция номер_образца` |
| [10_suffix_tree.cpp](code/10_suffix_tree.cpp) | текст, затем образец | отсортированные начальные позиции |

Индексы и номера образцов начинаются с нуля. Вхождения с перекрытием сохраняются. Отсутствие вхождений даёт пустой вывод. Пустой образец в поисковых примерах игнорируется. Словарные команды читают слова без пробелов, поисковые программы читают строки целиком. Порядок выдачи Ахо и Корасика описан в его главе.

Код рассчитан на размеры, помещающиеся в `int`, включая сумму `m + n + 1` для Z и число вершин автоматов. Это учебное ограничение, его надо сопоставить с условием задачи. Байт UTF-8 и буква русского текста не одно и то же: позиции здесь измеряются в байтах. Регистрозависимое точное сравнение не выполняет нормализацию текста.

## Проверка программ

Из этой папки запусти:

```sh
python3 verify.py
python3 verify.py --sanitize
```

[Проверяющий скрипт](verify.py) собирает каждую программу с предупреждениями как ошибками, сравнивает поисковые алгоритмы с независимым перебором, массивы с прямым вычислением определений, словарные команды с множеством Python. Есть полный перебор пар двоичных строк длины до пяти, случайные строки с пробелами и произвольными байтами, перекрытия, пустые образцы и повторяющиеся образцы. Генератор использует фиксированный seed `20261112`, чтобы результаты воспроизводились. Флаг `--sanitize` добавляет AddressSanitizer и UndefinedBehaviorSanitizer. Для запуска нужны Python 3 и компилятор `c++` с поддержкой C++17, для второго режима также поддержка указанных санитайзеров. Сборка идёт во временную папку.

## Связь с лекционным кодом и источниками

Наивный поиск, префиксная и Z-функция основаны на классических частях [лекции 24.10](../lecture_24_10/README.md). KMP и Бойер и Мур соответствуют [лекции 31.10](../lecture_31_10/README.md). Trie и compact trie взяты из простых классов [лекции 10.10](../lecture_10_10/README.md), суффиксное дерево из [лекции 7.11](../lecture_07_11/README.md). В новом Ахо и Корасике используются выходные ссылки вместо копирования списков ответов. Все исходные лекционные файлы сохранены.

В главах есть ссылки на конкретный код, выводы оценок и первичные публикации или университетские материалы для сверки определений. Суффиксный массив, суффиксный автомат, алгоритм Манакера, Укконен и Рабин и Карп не входят в согласованный разбор. Префикс-функция объясняется как необходимая основа KMP. Неуточнённое название «основная функция препроцессинга» из перечня лекций здесь не приравнивается к конкретному алгоритму.

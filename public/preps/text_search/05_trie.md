# Trie и compact trie

## Trie: дерево префиксов словаря

Корень соответствует пустой строке. Ребро добавляет один символ. Путь из корня задаёт префикс одного или нескольких слов. Вершина дополнительно хранит `terminal`: заканчивается ли здесь целое слово. Это важно, потому что существование пути ещё не означает наличие слова в словаре. [Классическая реализация](code/07_trie.cpp) взята из простого класса [лекции 10.10](../lecture_10_10/trie.cpp).

После вставки `he`, `her`, `hi` дерево выглядит так. Звёздочка означает `terminal`:

```text
root
  h
    e *
      r *
    i *
```

В словаре есть `he`, `her`, `hi`. Путь `h` существует, но вершина не терминальная, слова `h` нет.

### Вставка, поиск, удаление

Вставка идёт из корня по буквам. Недостающие рёбра и вершины создаются. В конце ставим `terminal = true`. Повторная вставка ничего не меняет: эта реализация хранит множество слов.

Поиск проходит тот же путь. Нет нужного ребра: ответ `false`. Все буквы пройдены: ответ равен `terminal` последней вершины. Длинное слово не должно засчитываться как его незаписанный префикс.

Удаление сначала находит слово, затем снимает терминальную отметку. В простом trie вершины остаются в массиве. Поэтому удаление `he` сохраняет `her`, а память не уменьшается. Для мультимножества вместо булевой отметки нужен счётчик, но это уже другой интерфейс.

Пример запуска обеих словарных программ:

```text
8
+ he
+ her
? h
? he
- he
? he
? her
? hi
```

Вывод по определениям множества и удаления:

```text
NO
YES
NO
YES
NO
```

### Стоимость

За операцию для слова длины `d` посещаем не более `d + 1` вершин. В коде переходы лежат в `map<char, int>`, один поиск или вставка перехода стоит `O(log(σ + 1))`. Получаем `O(d log(σ + 1))`. При фиксированном байтовом алфавите это `O(d)` с константой. Эти оценки следуют из циклов по слову и операций `map` в [коде](code/07_trie.cpp).

Вершин не больше `L + 1`, где `L` есть сумма длин когда-либо вставленных слов. Каждая новая вершина получает ровно одно входящее ребро, поэтому все рёбра и вершины занимают `O(L)` памяти. Из-за сохранения удалённых вершин речь именно об истории вставок. Если перейти на массив из 256 переходов в каждой вершине, память станет `O(256v)` даже при малом числе реально существующих рёбер.

## Compact trie: сжимаем цепочки

У промежуточной нетерминальной вершины с одним ребёнком нет развилки и не заканчивается слово. Такую цепочку можно заменить одним ребром, подписанным строкой. После вставки `bear`, `bell` получится:

```text
root
  "be"
      "ar" *
      "ll" *
```

Поиск сравнивает всю метку выбранного ребра, затем переходит к ребёнку. Для проверки целого слова завершение внутри ребра означает отсутствие слова. Если вставить `be`, конец ребра станет терминальным. Если вставить `bea`, ребро `ar` придётся разделить на `a` и `r`.

### Разделение ребра

Пусть текущая метка `ar`, а остаток вставляемого слова `ast`. Общая часть `a` имеет длину 1. Создаём промежуточную вершину после `a`, оставляем старый хвост `r` и добавляем новый хвост `st`:

```text
до:        "ar" -> старый ребёнок
после:     "a"  -> новая вершина
                      "r"  -> старый ребёнок
                      "st" -> новый конец слова
```

Если новый остаток закончился прямо на общей части, терминальной становится промежуточная вершина, без нового хвоста. Если общая часть равна всей старой метке, продолжаем вставку ниже. Именно эти случаи находятся в [SimpleCompactTrie](code/08_compact_trie.cpp).

Удаление снимает терминальность. Если ребёнок стал нетерминальным листом, ребро удаляется. Если он нетерминален и имеет одного ребёнка, две метки склеиваются. Терминальные вершины сжимать нельзя: потеряется информация о коротком слове.

### Идея структуры и цена конкретного кода

Программа хранит метки в `string` и передаёт остаток через `substr`. При поиске в худшем случае копируются остатки длин `d, d-1, ...`, их сумма `d(d+1)/2`. Для поиска получаем верхнюю границу `O(d² + dσ)`, где `dσ` учитывает просмотр исходящих рёбер. При фиксированном алфавите это `O(d²)`. Рекурсия может потребовать `O(d)` кадров. Компактность дерева сама по себе не делает такой код линейным.

При вставке и удалении дополнительно копируются старые метки во время разделения и склейки. Их длина может превышать длину обрабатываемого слова. Например, после вставки `a` и очень длинного `ab...b` удаление короткого `a` склеивает ребро с длинной меткой ребёнка. Поэтому стоимость модификаций описываем как `O(dσ + C)`, где `C` есть суммарное число копируемых символов, включая остатки входного слова и старые метки. Обещать для этого кода `O(d)` на вставку или удаление нельзя.

Эти издержки видны по вызовам `substr` в [программе](code/08_compact_trie.cpp). В следующей главе о суффиксном дереве метки будут храниться диапазонами исходного текста. На таком представлении не требуется создавать новую строку для каждого остатка. Различие между trie и сжатым деревом суффиксов показано также в [материалах Waterloo, раздел 5.2.1](https://cs.uwaterloo.ca/~plragde/flaneries/FDS/Text_Processing.html).

## Почему простого trie недостаточно для поиска в тексте

Trie отвечает, есть ли целое слово в словаре. Для поиска слов в произвольных местах текста можно запускать обход из каждого начала, но тогда одни и те же байты читаются многократно. Ахо и Корасик добавляет переходы, позволяющие продолжать поиск с подходящего суффикса без перезапуска на каждом начале.
